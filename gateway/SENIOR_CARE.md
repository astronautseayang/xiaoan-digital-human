# 适老主动关怀与紧急事件

运行入口仍然是 `human-gateway.service`。调度器随 FastAPI 启动，不需要再运行一份进程；保持单个 Uvicorn worker。Unity 源文件通过 `scripts/apply-unity-patches.py` 同步并由现有构建脚本编译。

## 默认行为

- `config/care.json` 使用 `Asia/Shanghai` 时区。08:00 至 21:00（两端包含）每天 14 次整点报时，附温水与安全走动提示。
- 12:00、18:30 为就餐及遵医嘱用药提醒，内容明确避免重复服药。可以修改 `reminders` 数组的 `id`、`time`、`title`、`text`，修改后重启网关。
- 定时提醒优先级 80，整点关怀 70，紧急求助 100。同一时间先显示用药/就餐卡片，确认后再显示整点关怀。紧急求助立即抢占普通对话与关怀。
- `artifacts/care.sqlite3` 持久化事件、时间点唯一键、确认状态、音频状态和推送状态。相同日期/任务只创建一次。重启后恢复尚未确认且未过期的事件和未完成音频；不会补发停机期间错过的用药提醒。
- 普通事件 30 分钟过期，紧急卡片 24 小时过期。确认仅关闭本地卡片，不取消已经排队的照护端告警。相同未确认求助在 30 秒内去重。历史及独立提醒音频保留七天；尚待外发的告警继续保留。

## 自然语言备忘提醒（2026-10-24）

文字输入和唤醒后的语音对话均通过同一提醒入口处理。以下请求直接写入 SQLite，保存成功才回复“已设置”，不依赖聊天模型口头承诺：

- `今天12点52的时候提醒我吃药`
- `明天下午三点半提醒我喝水`
- `十分钟后提醒我关火`
- `每天上午八点提醒我吃药`
- `查看提醒`
- `取消吃药提醒`，或 `取消提醒` 加回复中的八位编号；同名多条需指定编号。
- `取消全部提醒`

时区为 Asia/Shanghai。支持今天、明天、后天、每天及分钟/小时后的单条提醒。显式“今天”的时间已经过去时，不创建提醒，也不擅自改成明天。未指定日期的钟点若已过则安排明天，确认文字会给出实际日期。缺失时间、多时间、每周等暂不支持的规则会请用户确认。修改时间需先取消原提醒再设置。

到时显示备忘卡片并生成语音，可以点击或说“知道了”确认。用药卡片提示核对医嘱、避免重复服药。设备与网关需要保持运行；重启恢复计划，但不补发超过两分钟的过期提醒，避免延迟用药提示。每天的计划继续安排下一天。取消操作作用于未来计划，已出现的卡片仍需确认关闭。

验收脚本 `scripts/test-reminders.py` 使用隔离数据库验证保存、重启、去重、取消、过期及聊天双入口。实际一分钟后提醒已验证卡片、语音及确认，证据为 `artifacts/validation/companion-logic/reminder-live.json` 和 `reminder-live.png`。

## 客户端

`SeniorCareClient` 使用本地 HTTP 长轮询（`/api/care/events?wait=true&after=<version>`），有事件时立即返回；20 秒空闲超时后续接。版本号避免下载音频或更新 UI 期间丢失通知。断线后两秒重连，并读取未确认事件快照。

进入提醒时，`LocalHumanDemo.InterruptForCare()` 停止普通对话协程与音频，避免旧分句重新抢占。紧急求助先以本地 880Hz 提示音确认，再播放 TTS；卡片不依赖 TTS 是否成功。TTS 或下载失败会显示文字状态。后端语音锁按到达顺序处理，正在执行的单次 TTS 不会被强行中止，因而求助语音可能等待当前合成结束；本地提示音及卡片先行。

主界面采用近景角色、右侧大时钟、底部字幕与左侧语音光圈布局，配置和调试操作收纳到右上角“设置”抽屉，默认隐藏。深青绿主色搭配浅色圆角卡片。72 号时钟显示时分及中文日期；底部 44 号高对比字幕可滚动阅读，提醒正文 40 号。对话输入和常用操作已放大。提醒弹窗带背景遮罩，普通提醒使用青绿标识，紧急求助使用红色标识；大卡片期间隐藏重复的底部字幕，卡片下移以保留时钟与日期。大音量开关提供约 +6 dB 增益，选择保存在 PlayerPrefs。紧急提示自动使用增益。音频线程的限幅器把峰值限制在约 -1 dBFS，带快速衰减和缓慢恢复。

麦克风由 Python 离线关键词服务统一持有，默认监听“小安”及求助/确认词；Unity 原有分段关怀 ASR 监听仅在离线唤醒服务不可用时回退启用。待机不把周围谈话交给聊天模型，只有唤醒后才录音识别并自动对话。设置抽屉提供监听关闭开关，光圈可点击手动唤醒。普通播报、手动录音和音色录入期间暂停关键词检测，避免自唤醒。详见 [WAKE.md](WAKE.md)。

ASR 在识别结果中优先匹配 `跌倒`、`摔倒`、`救命`、`胸口疼`、`胸痛`；`知道了`、`我知道了`、`好的知道了` 的独立语句用于确认。关怀监听在开始说话时绑定卡片事件 ID，通过 `/api/asr?care_event_id=<id>` 只确认对应事件；空 ID 不关闭卡片，避免录音或识别期间新来的紧急事件被误关。未提供该参数的兼容入口确认当前最高优先级事件。含求助词时优先求助，避免被确认词覆盖。两个现有识别入口均消费 `care_command`，避免紧急文本继续送入普通聊天。参考音色录入内部的 ASR 不会产生关怀命令。

当前优先使用经过完整文件校验的 `models/asr/faster-whisper-base`，缺失时回退原有 tiny 模型；CPU int8、beam=5，解码前校正轻声音量并跳过近静音。基础模型在清晰“知道了”合成样本上通过了识别；音色合成质量差或口齿不清仍会影响结果，需要真人现场验证。

离线唤醒可用时待机关键词直接调用关怀命令，唤醒后约 0.7 秒静音结束录音、最长 15 秒。回退的关怀分段 ASR 则约 0.5 秒静音后上传、最长四秒一段。没有独立硬件跌倒传感器或声学回声消除；播放抑制期间后台关键词也不可用。扬声器/麦克风距离与实际房间噪声需要现场验收。

## 音频与动作

所有网关 TTS 使用 GPT-SoVITS `speed_factor=0.82`（语速放缓约 18%）、`fragment_interval=0.5`，每个音频片段增加 220ms 尾部停顿。后处理先以现有固定增益校正低电平输入，再在工作线程调用 FFmpeg：

1. 2.45kHz 中心、1.4 倍频程宽度、+2.5dB 的宽峰均衡，覆盖约 1.5–4kHz。
2. 3:1 动态范围压缩，15ms 起音、180ms 释放。
3. 先以 EBU R128 测量压缩后的综合响度和真峰值，再计算整段增益，目标 -16 LUFS，并受 -1.5dBTP 余量约束。峰均比过高时优先保留峰值余量，因此可能低于响度目标。短句也采用实测校正，避免单次动态 loudnorm 对短句意外衰减。
4. 最后约 -1dBFS 限幅，输出单声道 32kHz PCM16 WAV，并重写合法长度头以供 Unity 解码。

原始参考录音仍沿用已有的单次增益校正，避免对声音克隆参考反复施加 EQ/压缩。声音厚度主要取决于选用的参考音色；没有对基频进行强行降调。数字峰值不能推算扬声器在使用者位置的实际声压级，需在最终设备上调整系统音量并试听。

角色的前倾通过现有站姿/呼吸 Humanoid 肌肉曲线增加小幅 `Spine`、`Chest` 前倾；点头幅度从 .13 增至 .17，保留原有关切手势并提高微笑权重。继续由 Animator、VRM 和现有口型模块控制骨骼与表情。

## 照护端告警配置

`alert_webhook` 默认为空，此时界面写明“本地告警 · 尚未配置照护端”。填入实际接收端 URL 并重启网关后，紧急事件会 POST 以下 JSON：

```json
{"event_id":"唯一事件 ID","kind":"emergency","text":"求助提示","created":1790000000.0,"device":"本地数字人"}
```

接收端需以 `event_id` 去重。收到 2xx 才标记 `sent`；超时、网络错误或非 2xx 会持久化重试，指数退避到最长 300 秒。界面区分“正在推送”“推送失败，重试中”“已推送”。HTTP 接收成功不等同于照护人员已经阅读；系统没有自动拨打电话。当前没有提供真实照护端地址，因此尚未完成外部告警渠道的现场联调。

## 接口与验收

- `GET /api/care/events`：读取未确认事件；可附 `wait`、`after`。
- `POST /api/care/ack`：`{"id":"事件 ID"}`，确认指定事件。
- `POST /api/care/command`：`{"text":"知道了"}` 或求助语句，供本地交互接入。
- `POST /api/asr`：原有返回 `text`，增加 `care_command` 与 `event_id`。
- `GET /care-audio/<id>.wav`：提醒专用音频，不参与普通聊天的 200 文件滚动清理。
